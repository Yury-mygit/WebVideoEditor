# SlideSub Web — видео из картинок и субтитров

Веб-версия приложения из ТЗ «SlideSub» (`TZ_SlideSub.docx`, v0.1): длинный ролик (~1:30:00) из нескольких
статичных изображений, поверх — субтитры с точными таймингами. Рендер — FFmpeg на сервере.

## Состав

| Папка     | Что внутри |
|-----------|------------|
| `shared/` | Типы проекта, разбор/запись SRT, ASS, TXT, генерация ASS для рендера, проверки (ФТ-14, ФТ-26), тесты |
| `server/` | Node + Express: хранение проектов и файлов, рендер через FFmpeg, прогресс по SSE |
| `web/`    | React + Vite: редактор (сцены, превью, стиль, таймлайн, таблица реплик, окно сборки) |

Принцип из ТЗ сохранён: приложение не обрабатывает видео само, а формирует из проекта ASS-файл и команду FFmpeg.

## Запуск

Нужен Node.js 20+. FFmpeg ставится npm-пакетом `@ffmpeg-installer/ffmpeg` (бинарник приходит из npm-реестра,
отдельно ничего скачивать не нужно).

```bash
npm install
npm run dev        # сервер API на :3001 + Vite на http://localhost:5173
```

Сборка и запуск одним процессом (сервер раздаёт собранный фронтенд):

```bash
npm run build
npm start          # http://127.0.0.1:3001
```

Проверки:

```bash
npm test           # юнит-тесты shared (SRT/ASS/TXT, тайминги, проверки)
npm run typecheck
```

### Инструкция для пользователя

Страница `/instruction` (кнопка «? Инструкция» в редакторе) — пошаговая инструкция в картинках.
Скриншоты лежат в `web/public/guide/`, демо-файлы (4 фото и SRT) — в `web/public/guide/demo/`.
После изменений интерфейса картинки пересоздаются автоматически:

```bash
npm run guide:demo    # демо-фото и SRT (Python + Pillow), обычно не нужно
npm run guide:shots   # сборка, прогон сценария в headless Chrome, новые скриншоты
```

Скрипт поднимает отдельный сервер на порту 3102 с временной папкой данных, рабочие проекты не трогает.

### Переменные окружения сервера

| Переменная    | По умолчанию | Назначение |
|---------------|--------------|------------|
| `PORT`        | `3001`       | Порт (веб-интерфейс, API и MCP — на одном порту) |
| `HOST`        | `127.0.0.1`  | Интерфейс; для удалённого сервера — `0.0.0.0` |
| `DATA_DIR`    | `./data`     | Проекты, загруженные файлы, готовые ролики, логи |
| `SLIDESUB_PASSWORD` | —      | Общий пароль. Не задан — доступ открыт всем (только для локальной работы). Латиница, цифры и знаки, без пробелов |
| `PUBLIC_URL`  | из запроса   | Внешний адрес для ссылок в ответах MCP, например `http://server:9100` |
| `FFMPEG_PATH` | из npm-пакета | Свой FFmpeg, например системный `/usr/bin/ffmpeg` |
| `FONTS_DIR`   | `./fonts`    | Шрифты для субтитров при сборке. По умолчанию — PT Sans из репозитория, от шрифтов ОС не зависит |

## Пароль

Если задан `SLIDESUB_PASSWORD`, всё, кроме страницы инструкции и шрифтов, закрыто:

- **Браузер.** Сначала окно входа; после входа ставится кука на 30 дней, кнопка «Выйти» — в редакторе.
  Если сессия истекла во время работы, окно входа показывается поверх редактора, несохранённые правки не теряются.
- **curl, скрипты, MCP.** Заголовок `Authorization: Bearer <пароль>`.
- Неверный пароль — 401; больше 10 ошибок в минуту с одного адреса — 429.
- Соединение идёт по HTTP без шифрования. Внутри корпоративной сети это приемлемо; наружу сервер без HTTPS не открывать.

## MCP (работа через Claude)

На том же порту — `POST /mcp` (Streamable HTTP, без сессий). Подключение Claude Code:

```bash
claude mcp add --transport http slidesub http://server:9100/mcp --header "Authorization: Bearer <пароль>"
```

Инструменты: `list_projects`, `create_project`, `get_project`, `update_project` (название, длительность, разрешение,
стиль, сцены), `list_assets`, `import_asset_from_url`, `add_scenes`, `import_subtitles`, `get_subtitles`,
`edit_subtitles`, `check_project`, `start_render`, `render_status`, `cancel_render`, `list_results`.

Файлы через MCP не передаются (это неэффективно для картинок и видео) — инструменты возвращают готовые команды:

```bash
# загрузить материал (картинка JPG/PNG/WEBP, субтитры SRT/ASS/TXT или звук M4A/MP3/WAV); ответ — {"name": "..."}
curl -H "Authorization: Bearer $SLIDESUB_PASSWORD" -F "file=@photo.jpg" http://server:9100/api/projects/<id>/assets
# скачать готовое видео
curl -H "Authorization: Bearer $SLIDESUB_PASSWORD" -o video.mp4 "http://server:9100/api/projects/<id>/results/<имя файла>"
```

Сервер также умеет сам скачать материал по ссылке (`import_asset_from_url`).

REST для скриптов: `GET /api/projects/:id/assets`, `POST /api/projects/:id/assets/from-url`,
`POST /api/projects/:id/subtitles/import`, `GET /api/projects/:id/subtitles/srt|ass`,
`GET /api/projects/:id/results`, `GET /api/projects/:id/results/:name`.

## Развёртывание на Linux

```bash
git clone git@github.com:Yury-mygit/WebVideoEditor.git && cd WebVideoEditor
npm ci                 # ставит и FFmpeg для linux-x64 (@ffmpeg-installer)
npm run build
SLIDESUB_PASSWORD='...' HOST=0.0.0.0 PORT=9100 PUBLIC_URL=http://server:9100 npm start
```

Пример службы systemd (`/etc/systemd/system/slidesub.service`):

```ini
[Service]
WorkingDirectory=/opt/WebVideoEditor
Environment=HOST=0.0.0.0 PORT=9100 DATA_DIR=/var/lib/slidesub PUBLIC_URL=http://server:9100
EnvironmentFile=/etc/slidesub.env      # SLIDESUB_PASSWORD=...
ExecStart=/usr/bin/npm start
Restart=on-failure
```

Проверка развёрнутого сервера «от и до» (создаёт проект, загружает демо-материалы, собирает видео, скачивает MP4 и SRT):

```bash
SLIDESUB_URL=http://server:9100 SLIDESUB_PASSWORD='...' npm run smoke
```

## Данные

```
data/
  projects/<id>/project.json   — проект (формат из раздела 8 ТЗ)
  projects/<id>/assets/        — картинки, субтитры, звук (имена в проекте относительные)
  projects/<id>/renders/       — готовые MP4; во время рендера пишется *.part.mp4 и переименовывается в конце
  logs/render-*.log            — полная команда и вывод FFmpeg по каждому рендеру
```

## Что сделано (этап 1 — MVP, плюс часть этапа 2)

- Проекты: список, создание, автосохранение на сервер, предупреждение при закрытии вкладки с несохранёнными
  изменениями, отмена/повтор (Ctrl+Z / Ctrl+Y).
- Сцены (ФТ-10…15): загрузка JPG/PNG/WEBP кнопкой и перетаскиванием, замена картинки с сохранением тайминга,
  удаление, порядок перетаскиванием, длительность вручную, «Поделить поровну» с точностью до кадра, предупреждение
  о расхождении суммы и «Подогнать последнюю»; подгонка: обрезать / вписать с цветом полей / растянуть.
- Субтитры: импорт SRT, ASS, TXT (кодировка UTF-8 или Windows-1251 определяется сама), экспорт SRT и ASS,
  таблица с правкой на месте (виртуализирована под тысячи реплик), добавление и удаление, сдвиг таймингов
  выделенных или всех, подсветка замечаний (пересечения, короче 1 с, длинная строка, за пределами ролика),
  фильтр «только с замечаниями», Shift+Enter — ручной перенос строки.
- Стиль: шрифт, размер, жирный/курсив, цвет, обводка, тень, подложка с прозрачностью, позиция, выравнивание,
  отступ, максимальная ширина текста.
- Переходы (ФТ-16): между сценами — резко, плавно (crossfade) или через чёрный, по умолчанию для проекта и
  отдельно у сцены; проявление из чёрного в начале и затемнение в конце, звук нарастает и затихает вместе с ними.
  Переход идёт симметрично относительно границы сцен, поэтому тайминги сцен, субтитров и звука не сдвигаются.
  Вся логика — в `shared/src/segments.ts` (раскладка на отрезки «картинка» / «смешивание» в кадрах): по ней
  собирается видео (FFmpeg `blend` только на кадрах перехода — работает и в FFmpeg 4.1 без `xfade`),
  режется тестовый фрагмент и рисуется превью. Слишком короткие сцены — переходы укорачиваются, проверка предупреждает.
- Звук (ФТ-40…42): одна дорожка M4A/MP3/WAV/AAC/OGG (кнопка «+ Звук» в панели сцен или перетаскивание),
  идёт с начала ролика, лишнее при сборке отрезается; длина файла и кнопка «Ролик = длина звука»;
  в превью играет синхронно с курсором; на таймлайне — своя полоса; в MCP — параметр `audio` у `update_project`.
- Превью на canvas по тем же правилам, что и libass (размер шрифта, жадный перенос, высота строки);
  воспроизведение со звуком, шаг по кадрам, таймлайн с полосами сцен, звука и реплик и масштабами.
- Рендер: 1080p / 720p / 4K, 24–60 fps, H.264, вшитые субтитры; проверка проекта перед сборкой, очередь,
  прогресс и оставшееся время, отмена, скачивание результата, тестовый фрагмент 1 мин с текущей позиции,
  лог в файл, понятное сообщение об ошибке.
